Compatibility engine · Alpha

Adobe Creative Suite,
running on Linux.

Neutron is a compatibility engine built on Wine, DXVK, and vkd3d-proton, patched specifically for the way Adobe applications talk to Windows. Collider is the launcher. Mud Hut installs the apps.

Premiere Pro, Photoshop, and Lightroom have been used to deliver paid client work on this stack. After Effects and Media Encoder run but have not carried a paid job. The rest of the suite is untested or non-functional.

Display server

Wayland. Every fix here is developed and verified on a Wayland session. X11 has worked well in earlier testing and will likely keep working, but it is unverified — stability and usability there can't be guaranteed.

Why Wayland, specifically

X11 applies a single global scaling factor across every connected display, so a mixed-resolution setup can only ever be correct on one of them. A colorist running a 4K reference monitor beside a 1080p interface display, or an illustrator working across a laptop panel and a pen display, hits that limit immediately — and it is architectural, not a bug awaiting a fix. Multi-monitor at differing resolutions and scales is ordinary in professional creative work, so Wayland is the target.

  • Reference environment CachyOS · KDE Plasma (Wayland) · RTX 5070 on nvidia-open · ntsync kernel
  • Other setups Expected to work, being brought up, not yet validated
  • Licensing Bring your own Adobe subscription — no Adobe code is distributed
Steam Deck

Build available and Photoshop verified; other apps are included but untried. The AMD graphics path is early and not yet fully explored — GPU-accelerated features may behave differently than on the NVIDIA reference setup until that work is done. Testers welcome.

Why Linux

The apps were the only
reason you stayed.

Adobe's own forums have carried the same request for eight years running, from paying subscribers. The wording barely changes: I want to move to Linux, and Creative Cloud is the only thing stopping me. Neutron exists because that sentence should have an answer.

R1

You already decided. Adobe was the lock.

Nobody needs to be sold on this. Designers, editors, and students have been saying it publicly for years — one subscriber put it as plainly as it can be put: the only reason they still run Windows is Creative Cloud, and they'd drop it the day the suite ran elsewhere. The workarounds people reach for — a virtual machine, a second computer, dual booting — all cost either money or momentum. Neutron is the attempt to remove the lock rather than route around it.

R2

Your hardware shouldn't expire on someone else's schedule.

Windows 10 support ended and took a generation of capable workstations with it — machines that fail an upgrade check over a firmware module, not over performance. The Mac side of the trade has its own version: sealed machines, memory soldered at purchase, and the standing advice to buy every upgrade you might ever need on day one because you will never add one later. Between the two, a working editor is asked to replace an entire computer to solve what used to be a $90 problem.

Linux installs on the machine that got left behind. Add memory when a timeline demands it. Change the GPU. Add drives. Keep the tower for a decade and repair it in place. If you're currently weighing an expensive Mac refresh against moving to PC, this is the third option — the same Adobe apps, on hardware you specify.

R3

The workstation should work for you.

Consumer Windows now ships telemetry you can reduce but not switch off, promotional content threaded through the shell, and updates that arrive on Microsoft's timetable rather than yours. For a hobbyist that's an irritation. Mid-render, mid-deadline, on a machine you bought for one purpose, it's billable time. A Linux workstation runs the processes you put there and reboots when you say so.

R4

Most of the pro stack is already here.

Resolve ships a native Linux build and has for years. Blender, Houdini, Nuke, Krita, Inkscape, ffmpeg, and the entire color and encoding toolchain are native, and Autodesk Flame has run on Linux for decades — colorists and finishers have quietly worked this way the whole time. For most creative pipelines Adobe was the last missing piece, not the first.

Worth saying plainly: this is a compatibility layer, not a native port. It is alpha software, some applications don't run at all, and the ones that do still have rough edges. The status board above is the honest version.

Three projects, one stack

How the pieces divide

Each project owns one job and does not reach into the others. That separation is deliberate: it keeps compatibility work testable without a GUI, and keeps the launcher replaceable.

Neutron

Engine
LGPL v2.1

Neutron-Wine, DXVK, vkd3d-proton, a DirectComposition bridge, and an nvcuda wrapper — plus every Adobe-specific fix, from locale loader patches to display handling. Everything is exposed through a command-line interface. No GUI required.

github.com/Nico-LaFoucate/Neutron →

Collider

Launcher
Apache 2.0

A desktop application that finds your installed apps, checks that a prefix is healthy, launches it, and supervises it until it exits. It calls the Neutron CLI for anything compatibility-related and holds no fixes of its own.

github.com/Nico-LaFoucate/Collider →

Mud Hut

Installer
Ships inside Collider

A command-line installer that gets Adobe applications onto your machine without hand-building a prefix. It ships inside Collider as one-click install, and runs standalone for anyone who prefers a terminal.

github.com/Nico-LaFoucate/Mud-Hut →

Architecture

Where the fixes live

Neither Wine nor Adobe is broken. The defects live in the seam between two healthy systems, and that seam is where Neutron patches. One rule holds the project together: the launcher never touches compatibility.
